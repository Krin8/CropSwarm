# P42 smooth climate-fit preregistration

Use cached reference-farm inputs as of commit `af943b9`. Compare the baseline scorer with a separate heat-response what-if. All existing scoring files, parameter values, rankings and saved results are read-only. The revised function is a design choice informed by the gradual heat response seen in the P41 ridge curves. Its shape and width are fixed here independently of those estimates. No curve fitting, parameter tuning or new data.

## Fixed function

Keep the original crop-specific temperature threshold in degrees Celsius. For each complete historical crop window, count `h`, the days whose daily maximum strictly exceeds that threshold. Let `c` be the original allowed hot-day fraction multiplied by the window's actual number of days. Keep `c` fractional when applicable. The original heat screen passes when `h ≤ c`. In the what-if, replace that boolean with `1 − 3t² + 2t³`, where `t = clip((h − c + 5) / 10, 0, 1)`. The rule is continuous with flat slopes at both ends. Heat fit is 1 at `c − 5` hot days or below, 0.5 at `c` and 0 at `c + 5` or above. **Five hot days on each side is a design choice.** Keep the same band when P22 shifts crop thresholds or the policy fraction. Evaluate only attainable hot-day counts. Where the lower band extends below zero, even a zero-hot-day window can earn less than one.

The existing mean-temperature and rainfall pass/fail gates remain. A window failing either receives zero. Average the per-window climate-fit values as before, then average over the rotation slots. Keep the source tag NASA POWER and the crop catalog, with the smooth rule separately labelled as a design choice. Keep fallow's original value, missing-window behavior and all constraints and other metric values exactly.
